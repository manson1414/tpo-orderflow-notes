# 图鉴 02 · 订单簿（Order Book）

> **这一篇讲什么**：订单簿是什么、怎么读、以及它的四个致命局限。
> **配图**：无（原页面的图全部是平台设置界面，已按要求删除）。
> **来源**：译自 mmt.gg/learn/order-book，已删除全部平台操作说明。

**一句话**：订单簿是**所有正在等待成交的限价单的记录** —— 它描述的是市场**声明了什么意图**，而不是**发生了什么**。

---

## 一、订单簿是怎么工作的

市场里只有两种订单：

- **限价单（Limit Order）**：报出一个价格，然后**等**。
- **市价单（Market Order）**：跨过价差，**吃掉**正在等的那一方。

**订单簿，就是所有正在等的单子的记录。**

### 两侧

| 侧 | 名称 | 位置 | 原因 |
|---|---|---|---|
| 买 | **Bid（买价）** | 在当前价**下方** | 没人会出比自己能直接付的更高的价 |
| 卖 | **Ask / Offer（卖价）** | 在当前价**上方** | 同理 |

**最高买价和最低卖价之间的差 = 价差（Spread）** —— 当前价格就住在那里。

### 每个价位都带一个数量

这个数量，就是**价格要移动必须消耗掉的东西**：

- 一个价位**挂了很多** → 要把它清掉需要**真实的买卖力量**
- 一个价位**几乎没挂** → 价格**瞬间穿过**

### 整体读

把订单簿当一个整体看，它描述的是**市场「站着的意图」的形状**：
尺寸堆在哪里、哪里薄、两侧怎么比 —— **在任何成交发生之前，这些就已经全部可见**。

---

## 二、怎么读订单簿

### 1. 找墙（Walls）

**某档挂单远多于邻档 = 一堵墙。**

- 在价格**上方** → 是要买穿过去的卖单
- 在价格**下方** → 是要卖穿过去的买单

无论哪种，都是**价格会减速的地方** —— **前提是价格到达时它还在**。

### 2. 找缺口（Gaps）

**薄档是价格移动最快的地方**，因为几乎没有对手盘可打。

**「墙 + 紧邻其后就是缺口」是一种特定形状**：难到达，但**一旦越过就很快**。

### 3. 比较两侧

**下方买单很厚、上方卖单又薄又散**的订单簿，**下方的支撑远强于上方的压制**。
这和「两侧对称」的市场是**两个不同的市场** —— 即使价格看起来一模一样。

### 4. 看它怎么变

**这是静态读法漏掉的部分。**

- **扛过反复试探的挂单 = 真的**
- **价格快到时才出现、还没到就消失的挂单 = 本来就没打算成交**

**订单簿是一个活的物件。它随时间的行为，比它在任何瞬间的状态都更能说明问题。**

---

## 三、订单簿的局限

| 局限 | 说明 |
|---|---|
| **挂单不是承诺** | 任何限价单在成交前都可以撤。订单簿显示的是**声明过的**，不是**会发生的** |
| **存在幌骗（Spoofing）** | 挂出来就没打算成交、纯粹为了塑造订单簿外观的尺寸，在非监管市场很常见 |
| **只是可见的那部分** | 冰山单（Iceberg）只显示真实尺寸的一小部分；止损、止盈这类条件单**在触发前根本不在订单簿里** |
| **它没有记忆** | 订单簿描述的是**现在**。要看深度随时间怎么变，需要**订单簿热力图** |
| **它是单一交易所的** | 每个交易所只公布自己的订单簿 |

### 本篇需要关注的术语

| 术语 | 一句话 |
|---|---|
| **订单簿（Order Book）** | 所有未成交限价单的记录 |
| **限价单 / 市价单** | 前者报价格等待，后者跨价差立即成交 |
| **Bid / Ask** | 买价（在下方）/ 卖价（在上方） |
| **价差（Spread）** | 最高买价与最低卖价之差，当前价格所在 |
| **墙（Wall）** | 某档挂单远多于邻档，价格会减速处 |
| **幌骗（Spoofing）** | 挂着不打算成交的尺寸，只为影响观感 |
| **冰山单（Iceberg）** | 只显示真实尺寸一小部分的隐藏大单 |
